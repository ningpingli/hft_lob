# 单只股票 5 档 LOB 未来 60 秒收益率预测系统

## 0. 项目定义

### 0.1 业务目标

系统针对**单只股票**，使用连续竞价阶段的 **5 档买卖盘口 3 秒快照数据**，根据预测时刻及其之前的一段历史盘口序列，预测该股票**未来 60 秒收益率**。

核心任务定义：

```text
输入：
过去 L 秒 / N 个快照的 5 档盘口状态

↓

时序模型

↓

输出：
未来 60 秒连续收益率 y_hat
```

本项目首先是一个**时序收益预测系统**，不是完整高频交易系统。

必须把以下三个目标解耦：

1. Prediction：收益率是否可预测；
2. Signal：预测值是否可以转换成稳定交易信号；

# 2. 时间语义——P0

这是整个系统最重要的契约。

必须定义一个预测锚点：

```text
t = 当前可观测的最新盘口快照时间
```

输入窗口：

```text
X_t = [X_(t-L+3s), ..., X_(t-3s), X_t]
```

必须**包含 t 时刻快照**。

标签：

```text
y_t = return(P_t, P_(t+60s))
```

所以：

```text
历史 -------------------- t ---------------- t+60
                         ↑
                    prediction
```

禁止使用：

```text
X 截止 t-3s
label 从 t 开始
```

除非业务明确规定有 3 秒 execution latency。

### 2.1 样本契约

对于长度 N 的窗口：

```python
X = data[i-N+1 : i+1]
y = target[i]
```

不得使用：

```python
X = data[i : i+N]
y = target[i+N]
```

除非明确将后一行定义为预测时刻。

所有 Dataset 单元测试必须检查：

```text
max(timestamp(X)) == target_anchor_timestamp
```

---

# 3. 交易 Session——P0

上午、下午必须作为两个独立 session：

```text
Morning:
09:30:00 <= t < 11:30:00

Afternoon:
13:00:00 <= t < 14:57:00
```

禁止任何输入窗口跨越：

```text
11:30 → 13:00
```

禁止任何 60 秒标签跨越午休。

例如：

```text
t = 11:29:30
t+60 = 11:30:30
```

由于 11:30:30 已经不属于上午 session：

```text
该样本 label = invalid
```

绝不能使用：

```text
13:00:00 price
```

作为所谓的 “t+60 秒价格”。

同理：

```text
历史窗口：
11:29:xx
13:00:xx
```

不得拼成连续时序。

### 3.1 Session ID

每条数据必须显式保存：

```text
trade_date
session_id
timestamp
```

其中：

```text
session_id ∈ {AM, PM}
```

窗口和标签只能在：

```text
same trade_date
AND
same session_id
```

条件下构造。

# 4. 原始数据契约——P0

每条 3 秒快照至少包含：

```text
AskPrice1 ~ AskPrice5
AskVolume1 ~ AskVolume5

BidPrice1 ~ BidPrice5
BidVolume1 ~ BidVolume5

timestamp
trade_date
ticker
last
amount

```

即 20 个基础盘口特征。

必须验证：

### 时间质量

* timestamp 可解析；
* 单 session 时间严格非递减；
* 重复 timestamp 有明确去重策略；
* 3 秒频率允许轻微缺失；
* 必须记录真实 snapshot gap。

### 价格质量

正常情况下必须满足：

```text
BidPrice1 <= AskPrice1

BidPrice1 >= BidPrice2 >= ... >= BidPrice5

AskPrice1 <= AskPrice2 <= ... <= AskPrice5
```

### 数量质量

```text
volume >= 0
```

### 数据质量报告

每个交易日必须输出：

```text
row_count
missing_ratio
duplicate_count
crossed_book_count
one_side_missing_count
max_gap
p95_gap
stale_snapshot_ratio
invalid_level_order_count
```

# 5. 缺失数据策略——P0

禁止无限制 forward fill。

当前建议：

```text
gap <= max_ffill_gap
    可以 ffill
gap > max_ffill_gap
    标记该段数据 invalid
```

例如可以配置：

```yaml
max_ffill_gap_seconds: 6
```

具体值由数据分析确定，而不是写死。

同时新增：

```text
staleness_seconds
is_ffilled
```

内部质量字段。

模型可以选择不直接使用这些字段，但必须用于数据过滤与诊断。

整条盘口缺失不能简单认为：

> “上一个盘口仍然有效”。

尤其连续多个 3 秒快照缺失时，这会制造人为平滑。

---

# 6. Mid Price 定义——P0

研究目标默认采用有效双边 BBO：

```text
bid1 > 0
ask1 > 0
bid1 <= ask1
```

时：

```text
mid_t = (bid1 + ask1) / 2
```

如果只有单边报价：

```text
bid only
或
ask only
```

默认：

```text
mid_t = invalid
```

不建议用：

```text
mid = surviving_side_price
```

因为这可能制造虚假的价格跳跃。

但是在第一版数据处理中 我们还是使用单边价格作为中间价格

---

# 7. Label——P0

## 7.1 主标签

推荐使用 log return：

```text
y_t = log(mid_(t+60) / mid_t)
```

原因：

* 对称性更好；
* 时间收益可加；
* 数值性质优于简单收益率。

同时保留 simple return 用于业务解释：

```text
simple_return =
mid_(t+60) / mid_t - 1
```

但一个实验必须明确唯一 primary target。

---

## 7.2 Future timestamp matching

理论目标：

```text
future_time = t + 60 seconds
```

允许的实际快照：

```text
closest snapshot around t+60
```

必须设置 tolerance：

```yaml
target_horizon_seconds: 60
target_tolerance_seconds: 3
```

例如：

```text
期望：10:01:00
实际：10:01:00     OK
实际：10:01:03     可配置接受
实际：10:01:15     INVALID
```

禁止无上限：

```python
first timestamp >= t + 60
```

否则严重缺失数据会把：

> “60 秒收益”

变成：

> “74 秒 / 120 秒 / 90 分钟收益”。

---

# 9. 输入窗口——P0

不要再把：

```text
history_length = 180
```

含糊解释为“180 秒”。

在 3 秒快照下：

```text
180 snapshots × 3s = 540s
```

也就是 **9 分钟历史**。

配置必须统一窗口单位，除了标签 horizon 使用s,特征窗口使用数字int：

```yaml
history_length: 30
prediction_horizon_seconds: 60
```

# 12. Normalization——P0

Normalization 必须满足：

> 任意样本 t 的 normalization 参数只能来源于 t 之前可获得的信息。

绝对禁止：

```text
full dataset mean/std
```

也不能先对完整数据计算统计量后再 split。

支持两种模式：

### Train-only normalization

```text
fit(train)
transform(train)
transform(validation)
transform(test)
```

### Causal rolling normalization

预测 t 时：

```text
mean/std only from data < t
```

并且 normalization state 必须能够序列化，用于线上 inference。

必须测试：

```text
修改未来数据
不得改变过去样本的 normalized value
```

这是防泄漏的核心测试。

# 14. Overlapping Label 问题——P0

3 秒采样、60 秒 horizon 意味着：

```text
连续约 20 个样本的未来区间高度重叠
```

因此：

```text
10:00:00 → 10:01:00
10:00:03 → 10:01:03
10:00:06 → 10:01:06
...
```

这些 label 不是独立样本。

所以禁止把：

```text
N = 100000
```

简单理解成：

> 100000 个独立统计样本。

评估必须显式处理 serial correlation。

至少报告：

```text
daily metric
mean daily metric
metric std
confidence interval
```

必要时采用：

```text
block bootstrap
```

而不是普通 IID bootstrap。

# 16. Walk-forward Evaluation——P0

单次 60/20/20 不足以证明高频 alpha 稳定。

必须支持 walk-forward。

例如：

```text
Fold 1
Train: 1~3月
Val:   4月
Test:  5月

Fold 2
Train: 1~4月
Val:   5月
Test:  6月

Fold 3
Train: 1~5月
Val:   6月
Test:  7月
```

至少得到：

```text
IC by fold
RankIC by fold
MAE by fold
PnL by fold
```

这样才能判断：

> 模型是真的稳定，还是碰巧在某段行情有效。

# 21. Evaluation Metrics——P0

不能只报告一个 Pearson IC。

对于**单只股票时序预测**，建议将其明确称为：

```text
TS-IC
```

而不是传统横截面 IC。

必须报告：

| 类型   | 指标                    |
| ---- | --------------------- |
| 拟合误差 | MAE                   |
| 拟合误差 | RMSE                  |
| 线性关系 | Pearson TS-IC         |
| 排序能力 | Spearman RankIC       |
| 方向   | Direction Accuracy    |
| 上涨预测 | Precision / Recall    |
| 下跌预测 | Precision / Recall    |
| 稳定性  | Daily IC mean/std     |
| 稳定性  | ICIR                  |
| 稳定性  | Positive IC Day Ratio |

其中：

```text
ICIR =
mean(daily_IC) / std(daily_IC)
```

---

# 22. 不要把 R² 作为核心指标

R² 可以报告，但一分钟收益的：

```text
R² ≈ 0
```

甚至轻微负数并不自动意味着没有交易预测价值。

金融时序更关心：

```text
correlation
ranking
direction
economic value
stability
```

---

# 23. 分桶分析——P0

对预测值按照：

```text
prediction quantile
```

至少分：

```text
10 bins
```

检查：

```text
mean realized return by prediction decile
```

理想结果应近似单调：

```text

Q1  strong negative realized return
...
Q5  around zero
...
Q10 strong positive realized return
```

这个分析对于判断模型是否真的学到 alpha 非常重要。

# 36. Model Release Gate

模型不得因为：

```text
val_loss 最小
```

就进入生产。

至少通过四层 Gate：

```text
Gate 1
Data Quality

Gate 2
Statistical Predictability

Gate 3
Temporal Stability

Gate 4
Economic Value
```

## Gate 1

无：

```text
future leakage
cross-session samples
invalid label
split leakage
```

## Gate 2

在严格 OOS test：

```text
模型显著超过 zero / linear baseline
```

并报告置信区间。

## Gate 3

不是单个月份贡献全部 alpha。

要求：

```text
多数 test days / folds 保持同方向预测能力
```

# 41. MVP 最终验收定义

第一阶段成功不是：

```text
CNN train loss 收敛
```

也不是：

```text
test IC > 0
```

而应该是：

```text
1. 时间语义严格正确
2. 无 future leakage
3. 无 session crossing
4. 数据完全可追踪
5. OOS chronological evaluation
6. walk-forward 多阶段稳定
7. 明显超过简单 baseline
8. 结果能够按日/时间/市场状态解释
9. 模型 inference 可复现
10. 若宣称可交易，则 after-cost backtest 有效
```
